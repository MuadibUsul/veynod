# 联邦目录的隐私边界（P4-4）

> 任务：`fedv2-p4-4-privacy-complaint`（20/24）。对应愿景 §9.5、§12.4、§13.1，F-026。
> 机器可读版本：`GET /v1/federation/privacy`。参数见 `OWNER_DECISIONS.md` M 节。

## 1. 三层可见范围

| 范围 | 内容 |
|---|---|
| **上架后所有人可见** | 一句话介绍、能力标签、接活状态；处罚（生效中与历史）；**已结案**的投诉：类别、结果、日期、对应处罚 |
| **上架后、所有者选择公开才可见** | 交付率（completion）、验收率（acceptance）、回应速度（response）、Skill 评分（skills）、合作情况（cooperation） |
| **只有合作双方可见** | 履约证明（写着双方地址、条款哈希、结果哈希、签名）、委派条款与结果、聊天内容 |
| **任何人都看不到** | 任务正文、聊天正文、交付结果、任务 id、证明内容、和谁合作过、举报人、举报陈述、证据、运营人员备注、未结案的投诉、核验备注 |

## 2. 所有者的公开选择

`PUT /v1/federation/directory/listing` 的 `disclosure` 字段：`{completion, acceptance, response, skills, cooperation}`，默认全部公开。

- 隐藏的项，别人看到的是 `{"hidden_by_owner": true}`；自己看自己仍是完整的。
- **隐藏的项不参与排序**：交付率或验收率被隐藏时，“过往表现”按中性 0.5；回应速度被隐藏时按“未知”。隐藏不能让排名变好。
- 处罚和已结案投诉**不能隐藏**：这是安全信息。
- 未上架的工作区：声誉只给它自己和与它有连接的工作区看（P4-2）。

## 3. 投诉记录（举报的公开部分）

- **只公开已结案的**：成立（`DECIDED` / `APPEAL_WINDOW` / `CLOSED`）、驳回（`DISMISSED`）、证据不足（`INSUFFICIENT_EVIDENCE`）。还在处理中的不公开，也不计数：举报不等于定性（愿景 §13.1）。
- 每条只给：类别、结果、是否终局（申诉期内为否）、对应处罚类型、结案日期。
- 汇总：已结案数、成立 / 驳回 / 证据不足各多少、成立的按类别分布、近一年成立数、申诉中数量。

## 4. 投诉与声誉的关联

- 声誉 `governance.complaints` 带上述记录。
- 目录排序的安全系数：近一年每有 1 条成立的投诉 ×0.9，最低 0.6；与历史处罚的 ×0.8 相乘。排名解释里写明。
- 被驳回或证据不足的投诉不影响任何分数。

## 5. 为什么查不回私聊（F-026）

- 目录、搜索、条目、声誉页都不含任务正文、聊天、任务 id，也不含条款哈希、结果哈希、签名：拿不到可以“猜内容再比对哈希”的材料。
- 履约证明只给双方；局外人取证明得到空列表。
- 测试 `tests/test_federation_privacy.py` 用一段机密在聊天、任务目标、交付结果里各出现一次，再从局外人能访问的所有入口（搜索、条目、声誉、证明）取数据，逐一确认不含机密、任务 id、对方地址和任何哈希或签名。

## 6. 保留期

- 履约证明、投诉结案记录、核验记录：长期保留（只读追加），用于核验和申诉。
- 聊天正文的 90 天清理（见 B4）尚未实现。
