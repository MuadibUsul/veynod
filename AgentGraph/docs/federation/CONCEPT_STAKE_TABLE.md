## 0. 一句话

工作区之间开一桌德州扑克，买入用 **M（百万 token）** 计价；协议锁定后开打；打完后输家欠赢家一笔 **算力债**，赢家用它让输家的 agent 替自己的项目干活；输家没还清之前不能再上桌——和共享单车“欠费未结清不能开下一辆”是同一个模型。

## 1. 先把“质押的到底是什么”说清楚

原始说法是“赢家使用输家的 token”。订阅账号的额度**转不出去**，也**不应该把账号或凭证交给别人**，所以可落地的标的只有一种：

> **质押的是一份履约承诺：我的工作区的 agent，用我自己的模型额度，为对方完成至多 N M token 的委派任务。**

赢家拿到的是一张**算力债权（claim）**，不是 token，更不是账号：

| | 赢家能做 | 赢家不能做 |
|---|---|---|
| 债权 | 向输家工作区发委派任务，用量从债权里扣 | 拿到输家的凭证、登录态、API key |
| 执行 | 任务在输家的机器、输家的 agent、输家的订阅里跑 | 指定输家用哪个账号、绕过输家的权限范围 |
| 结果 | 收到交付物和用量回执，验收 | 看到输家工作区的其他内容 |

这正好落在联邦已有的东西上：**委派（delegation）+ 用量回执（model_tokens）**。牌桌只是新增了“这笔委派由谁出额度”的来源。

“协议锁定后自动可用”的含义因此是：结算时系统自动给赢家开一份**常设委派授权**（standing grant）——在锁定时双方的人已经签过的范围内（任务类别、数据级别、每日上限、有效期），赢家发来的委派**不需要输家的人逐单点接受**，直接进入输家 agent 的队列。范围之外的仍然要人批。

## 2. 单位：M 不能只是“一百万 token”

token 之间差价巨大：缓存读取的输入 token 几乎不值钱，旗舰模型的输出 token 比小模型贵一个数量级。如果只写“1 M”，输家会用最便宜的方式把它烧完。

- **标准 M（sM）** = 按公开权重折算后的 token：模型档位系数 × （输入、输出、缓存读、缓存写各自的权重）。权重表随协议一起哈希进 `terms_hash`，锁定后不变。
- 协议写明**最低模型档位**（例如“不低于某一档”）。用低档模型交付，按系数折算，不算违约，但扣得少。
- 牌桌筹码与 sM 脱钩：筹码只是桌内积分，只有**最终名次**换算成债权。这样一桌的最大损失在锁定时就是确定的（= 买入）。

## 3. 牌局形式

| 选项 | 说明 | 建议 |
|---|---|---|
| 单挑 SNG（2 人，固定买入，打到一方筹码归零） | 没有合谋空间，债权债务一对一 | **第一版** |
| 多人 SNG（6/9 人，固定买入，按名次分配） | 好玩，但有合谋送筹码、债务多对多 | 第二版 |
| 现金桌（随时补码） | 损失无上限，欠债滚雪球 | 不做 |

- **谁在打**：人打，或者 agent 打（人只设定策略）。agent 对局更贴合产品——“谁家的 agent 更会打”本身就是可看的内容和排行榜——但对局本身也烧 token，且要防 agent 自己加注。无论谁打，**上桌、买入、签协议必须是人**（与“报价由人发出”一致）。
- **发牌可验证**：每位玩家入座时提交随机种子的承诺，服务器也提交一个；洗牌 = 全部种子的哈希；每手结束公开，任何人可复算。手牌历史只追加、可导出。
- **跨部署**：牌桌由一个部署主持，其他部署的工作区作为远端入座，主持方就是发牌方。不做免信任的密码学发牌（mental poker），太重。
- **反合谋**：`integrity` 里已有“同一控制人”关联——关联的工作区不能同桌；多人桌再加送筹码的异常检测。

## 4. 生命周期

```
牌桌    OPEN → SEATED → LOCKED → PLAYING → SETTLED → CLOSED
                  └→ VOID（锁定前有人离开 / 发牌方故障：全部解锁，无债务）

债务    OWED → DELIVERING → CLEARED
          └→ OVERDUE → DEFAULTED（押金划给赢家，仍未清的部分继续挂账）
          └→ EXPIRED（赢家在有效期内没用完：剩余作废，不算输家违约）
          └→ WAIVED（赢家主动免除）
```

- **LOCKED**：所有入座方的人对同一个 `terms_hash` 签字（买入、名次分配、权重表、最低模型档位、委派范围、每日交付上限、债权有效期、押金）。此后任何一方退出都按弃权处理。
- **SETTLED**：按名次生成债权和债务，账本记一笔（借方 `owe:<输家>`，贷方 `claim:<赢家>`，相加为 0），同时开常设委派授权。
- **DELIVERING**：每一单委派交付并验收后，用量回执里的 sM 从债务里扣。被拒收的交付不扣（争议走已有的裁定流程）。
- **CLEARED**：债务归零，授权自动撤销，门禁自动解除。

## 5. 共享单车模型的完整映射

| 共享单车 | 牌桌 | 说明 |
|---|---|---|
| 押金 | **上桌押金**（SIM 积分，进已有的托管账户） | 订阅额度没法预扣，所以押的是积分；违约时划给赢家 |
| 信用免押 | 履约记录好的工作区免押金、额度更高 | 用 `reputation` 的履约证明，新增“按时交付率” |
| 按时计费 | 按 sM 计量扣减 | 用量回执 |
| 欠费不能开下一辆 | **有未清债务不能上桌** | 自动门禁，见下 |
| 补缴后立刻恢复 | 清偿后立刻解除 | 是门禁，不是处罚，不留黑记录（逾期次数另计入信誉） |
| 起步价/封顶 | 单桌买入上限、每周净输上限 | 按信用分档 |
| 车坏了不计费 | 赢家不派活、派的活超出范围、债权过期 | 都不算输家违约 |

**门禁只锁牌桌，不锁别的。** 欠债的工作区必须还能收委派、发消息、交付——否则它没法还债。门禁检查只放在“入座”和“开桌”两个入口，返回 `FED_E_DEBT_OUTSTANDING`，并附上还欠多少、欠谁、怎么清。

**逾期怎么算。** 订阅有 5 小时和每周的速率限制，输家不可能一夜交付 20 M。协议里写**每日交付上限**（例如 2 sM/天），到期日 = 债务 ÷ 每日上限 × 宽限系数。只有“赢家发了范围内的委派、输家在时限内没接或没交付”才累计逾期；赢家不派活时时钟暂停。

**清偿方式（多给几条路，欠债才不会变成死账）：**
1. 交付委派工作（默认）；
2. 用 SIM 积分按挂牌比例折抵；
3. 赢家免除；
4. 债权过期自动作废；
5. （后续）债权转让给第三方，由输家向第三方交付——先不做，转让会让它变得像可流通的代币。

## 6. 最难的三个问题

**① 用量是自报的。** `OWNER_DECISIONS` C5：平台只自测分钟数，token 靠自报。输家有动机多报（用废话把债烧完），赢家有动机拒收（白拿结果）。
- 用量由 **veynod CLI worker** 上报并签名（0.7.0 起 agent 通过各自的 CLI 运行，worker 能读到每次调用的真实用量），不接受手填；
- 每单委派设上限（例如 ≤ 0.2 sM），单次争议的敞口有限；
- 扣减以**验收**为准；拒收率、单位产出 token 数异常进 `integrity` 的异常清单；
- 仍然解决不了的进已有的争议裁定。

**② 消耗的 token ≠ 交付的价值。** 赢家真正想要的是“活干完”，不是“烧掉 5 M”。可选的替代计价：按验收通过的任务计件，token 只作上限。建议第一版仍按 sM 计量（简单、与买入同单位），但协议里允许赢家给每单写验收标准。

**③ 多人桌的债务方向。** 6 人桌有 3 个输家、2 个赢家，谁欠谁？建议结算时按确定性算法做**两两配对**（最大输家配最大赢家，依次拆分），每对之间建一条**仅限本桌债务的连接**（范围只含委派，随债务清偿自动失效）。不做“对桌池欠债”，那需要一个中央调度。

## 7. 落到现有模块上

|---|---|---|
| `market.py`（Offer→Contract→Receipt） | 新增第四条价值流 `stake`：协议即 Offer，锁定即 Contract | 状态机、`terms_hash` 字段集 |

## 8. 两条必须先过的风险

这两条不是工程问题，工程上绕不过去。

**① 赌博定性。** 用有市场价的东西（模型额度明码标价）押德州扑克的输赢，在中国大陆和大多数法域都落在赌博监管范围内；**组织牌局的平台一方**的风险高于玩家，抽成会进一步加重。`ICD_P5_MARKET.md` §0 已经定了原则：结算介质、托管主体、合规评估没定之前只做模拟。牌桌应该守同一条线：
- 纯 SIM 版（积分不能买、不能提现、不能换算力）风险低，但也就没有“赢家用输家的 token”；
- 一旦债权能换成真实算力，就是真实价值的输赢，**需要律师意见后才能开**；
- 降低风险的形态（不等于合规，仍需评估）：仅限互相认识的邀请制小圈子、平台永久零抽成、严格的买入和周净输上限、债权不可转让不可折现。

**② 模型服务商的条款。** 个人订阅（Claude Pro/Max、ChatGPT Plus 等）普遍禁止共享账号和转售额度。“输家的 agent 替赢家干活”比交出账号好得多，但用个人订阅为第三方提供服务仍可能违反条款，后果是输家的账号被限制。建议协议里声明额度来源，**只把 API key 或团队/企业计划的额度当作可质押来源**，个人订阅给出明确提示并由 owner 决定是否允许。

## 9. 往外拓展

- **通用化：牌桌只是一种“裁判”。** 真正的新原语是**对赌合同**：双方锁定额度 + 一个可验证的结果来源 → 生成算力债。扑克之外可以接：agent 基准对决（同一道题两家 agent 各做一遍，第三方评审）、谁先合并 PR、预测 CI 是否通过。技能型对决比扑克更贴近产品，法律上也更容易辩护，建议把它作为并列甚至优先的第一个裁判。
- **互助池而不是对赌。** 双方本来就各拿出 N M 互相帮忙（纯算力互换，没有输赢），牌局只决定**谁的活先做**。没有净输赢，风险性质完全不同，而“共享单车门禁”照样成立——先被服务的一方没回报就不能再发起互助。这是最保守、最可能直接上线的变体。
- **信用体系。** 新工作区：必须押金、买入 ≤ 1 sM、同时只能有一笔未清债务。按时清偿 N 次后升档：免押、更高买入、可上多人桌。逾期降档。
- **赛季与战队。** 工作区战队、赛季排行榜、可回放的手牌、agent 对局观战。
- **负责任参与。** 每周净输上限、连输冷静期、owner 可给整个工作区关掉牌桌、agent 永远不能自己决定上桌或加买。
- **债权看板。** 赢家看“我还有多少 sM 可用、哪些输家当前在线有余量”；输家看“还欠多少、今天的交付上限用了多少、按现在的速度哪天清”。

## 11. 分期（如果立项）

1. **P6-0 决策**：T1–T10，法律与条款评估。
2. **P6-1 算力债与门禁**：`sM` 账本单位、债权/债务、常设委派授权、用量扣减、`FED_E_DEBT_OUTSTANDING`。先接互助池，不含任何牌局。
3. **P6-2 SIM 单挑牌桌**：发牌、承诺-公开、手牌历史、SIM 买入与押金；输赢只影响 SIM。
4. **P6-3 牌桌接算力债**（过了 §8 之后）：名次 → 债权；信用分档。
5. **P6-4 多人桌、agent 对局、跨部署主持、通用裁判接口。**

P6-1 独立于牌局就有价值：它给现有的 task 委派补上了“先干活、后还工”的互换模式。
